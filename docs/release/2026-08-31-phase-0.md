## Database safety evidence

Read-only production checks performed before any migration:

- Business/public application tables observed have RLS enabled.
- Direct `anon` read of `public."User"` returns `permission denied`.
- Direct `anon` read of `public.v2_profiles` returns `permission denied`.
- Supabase Security Advisor reports three `SECURITY DEFINER` functions. Inspection shows explicit auth/role checks on the authenticated functions, and the public emergency lookup is intentionally callable by `anon` with field-visibility filtering.
- `_prisma_migrations` is materially behind the real production schema; production also contains newer `v2_*` tables. Therefore no new Prisma migration should be applied until backup/restore and migration drift are resolved.

The release branch contains `prisma/migrations/20260831190000_harden_public_rls/migration.sql`, but this migration is intentionally **not applied to production during Phase 0**.
